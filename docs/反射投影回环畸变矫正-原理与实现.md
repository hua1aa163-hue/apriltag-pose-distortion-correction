## 2. 系统定义

系统中有三个坐标空间：

1. 输入图像坐标 `s=(u,v)`：完整 1920×1080 原始内容。
2. 投影仪坐标 `p=(x_p,y_p)`：Windows 投影桌面的像素坐标。
3. 相机坐标 `c=(x_c,y_c)`：MV-CS200-10GM 抓取画面中的像素坐标，当前为 5472×3648。

反射投影光路形成前向映射：

`c = F(p)`

畸变矫正要做的不是把已经拍到的相机图片拉直，而是提前生成投影端预扭曲图。给定希望相机看到的规则位置 `c*`，求投影位置：

`p = F^(-1)(c*)`

当这个预扭曲图经过真实投影、反射和相机观察后，几何变形会互相抵消，相机最终看到规则图像。

## 3. 为什么采用 Gray Code + 点阵回环

单张点阵只能提供有限的稀疏对应关系（本次 27×7 为 189 组），足以做初步几何估计和验证，但不足以稳定表示反射面上的局部非线性。程序因此使用两层标定：

- Gray Code 建立稠密投影—相机对应关系，负责得到全局初值。
- 用户配置的点阵负责相机回环测量残差，再迭代修正网格。

这种组合兼顾了覆盖率和最终可验证性，也可以在 Gray Code 已完成后从 `.dmap` 恢复，不必每次重新投完 34 张图。

## 4. Gray Code 稠密映射原理

### 4.1 图卡数量

程序使用 8×8 投影单元。1920 方向有 240 个单元，需要 8 位；1080 方向有 135 个单元，也需要 8 位。每一位都投正常图和反相图，另外投全黑和全白参考图：

`2 + 2 × (8 + 8) = 34 张`

### 4.2 正反图差分

对同一 Gray Code 位，分别拍摄正常图 `I+` 与反相图 `I-`。若两者亮度差小于最小对比度，该相机像素视为无效；否则亮度较高的一侧决定该位是 0 还是 1。全白与全黑图用于排除阴影、不可投影区域和低对比区域。

Gray Code 的相邻码字只变化一位，能降低边界处少量曝光或错位对解码结果的影响。解出的 Gray 值通过逐位异或转换成二进制投影单元坐标。

### 4.3 映射方向

解码首先得到“相机像素 → 投影单元”。程序随后按投影单元聚合相机像素质心，保存为“投影单元 → 相机坐标”的 `.dmap`，便于直接计算 `F(p)` 和局部雅可比矩阵。

## 5. 可配置目标外接尺寸的正确处理

目标外接宽高（本机实测为 1777×687）是完整 1920×1080 输入经过逆映射后，在同一 1920×1080 输出画布中的自然外接尺寸。它不表示：

- 输入图先裁成 1777×687；
- 在画布中心预先画一个规则的 1777×687 矩形；
- 把扭曲图强制缩放或裁剪为该尺寸。

程序先在相机空间构造横平竖直的目标网格，再通过 `F^(-1)` 求每个控制点的投影坐标。反射光路在横纵方向的缩放不同，因此目标网格的宽、高必须独立求解，不能预设为 16:9。求解器迭代调整相机目标网格宽高，使完整输入边界经逆映射后的自然外接框满足：

`width(BBox(F^(-1)(c*)))) ≈ targetWidth`

`height(BBox(F^(-1)(c*)))) ≈ targetHeight`

本机离线求解结果为 `1776.9×687.3`；一次回环后为 `1777.2×687.3`。

## 6. 数值反演与网格渲染

### 6.1 局部反演

对每个目标相机点 `c*`，先在稠密映射中找最近有效投影单元作为初值，然后对前向映射做数值求导，得到局部雅可比矩阵：

`J = ∂F / ∂p`

迭代更新：

`p_(k+1) = p_k + J^(-1) × (c* - F(p_k))`

每步位移有限幅，避免因局部噪声跳到无效区域。

### 6.2 分片仿射

程序使用界面填写的列×行内部控制点，并向完整输入边界外推一圈控制点。每个四边形拆成两个三角形；渲染时对目标三角形逐像素求重心坐标，再从原始 1920×1080 内容中取样。这样可以表达透视、旋转、梯形和反射曲面引入的局部非线性。

### 6.3 投影前安全检查

在真正切换桌面前，程序检查：

- 自然外接框是否接近用户填写的目标宽高；
- 扩展网格是否越出 1920×1080；
- 三角形方向是否一致，是否翻折或退化；
- 点阵最小间距是否足以让 13 像素白点被相机分辨。

本机初始安全检查结果：448 个三角形，翻折 0，退化 0，最小点间距 63.7 投影像素。

## 7. 点阵回环

投影校正点阵后，相机在每个预测坐标附近做局部亮斑质心定位。相比全图固定阈值，这种方法能适应反射系统中的强烈亮度不均和暗背景。

第 `i` 个点的相机残差为：

`e_i = c_i* - c_i(observed)`

利用稠密映射的局部雅可比把相机残差换算成投影坐标修正：

`Δp_i = λ × J_i^(-1) × e_i`

其中 `λ=0.75` 是松弛系数。验收指标为：

`RMS = sqrt(Σ ||e_i||² / N)`

本机第一次回环即得到 `RMS=0.583 camera px`，因此无需继续迭代。

## 8. 自动位置与固定位置

### 自动位置

直接保留标定求出的 `F^(-1)` 坐标。它反映当前投影仪、反射面和相机的自然对应关系，是默认推荐方案。本机结果约为 `(77.0,244.1)`。

### 固定位置

先生成同一扭曲形状，再统一增加平移量：

`p_fixed = p_auto + (targetTopLeft - autoTopLeft)`

固定位置不会重新缩放或重新弯曲内容。界面允许输入左上角 X/Y；示例 `(120,260)`。程序会在渲染前检查完整自然外接框；若固定位置会越出 1920×1080，则明确报错并停止，避免静默裁掉内容。

## 10. 工程结构

- `Camera/HikCameraService.cs`：海康 MVS SDK 枚举、连接、抓图。

- `Imaging/MeshWarp.cs`：网格检查、分片仿射和两种放置方式。
- `Imaging/BatchWarpService.cs`：文件夹递归处理、子目录保留、自动/固定两种输出。
- `Calibration/LoopCalibrationController.cs`：完整 Gray Code + 点阵回环。
- `Calibration/LoopOnlyController.cs`：从 `.dmap` 故障恢复并继续回环。
- `MainForm.cs`：协调四个 Designer 子界面并保护桌面/任务生命周期。
- `UI/*.Designer.cs`：相机、投图、标定、批处理四个可在 Visual Studio 设计器中移动控件的 `UserControl`。

## 13. GitHub 参考程序与采用关系

### kamino410/procam-calibration

仓库：<https://github.com/kamino410/procam-calibration>  
许可证：MIT。

该项目使用棋盘格与 Gray Code 标定投影仪—相机系统，推荐对不同棋盘姿态采集多组数据，并利用棋盘角附近的局部单应性提高投影像素对应精度。它适合需要相机和投影仪内外参、三维几何尺度的场景。本项目采用其“结构光建立投影—相机对应”的核心思路，但由于目标是固定反射光路中的端到端图像预畸变，没有照搬多姿态棋盘和双目标定流程。

### punpongsanon/graycode-procam-calibration

仓库：<https://github.com/punpongsanon/graycode-procam-calibration>  
许可证：MIT。

该项目在 Windows、OpenCV 与第二显示器环境中投射 Gray Code，保存相机—投影像素查找表 `c2p.csv`，并说明需要按第二显示器位置设置投图坐标。它验证了“相机充当投影仪的眼睛、Gray Code 建立像素查找表”的工程路线。本项目将投图窗口改为用户要求的 Windows 桌面切换，并把查找表扩展为可插值、可求雅可比、可故障恢复的 `.dmap`。

### OpenCV opencv_contrib / structured_light

仓库：<https://github.com/opencv/opencv_contrib/tree/4.x/modules/structured_light>  
关键接口：`GrayCodePattern`。

OpenCV 的实现把 X/Y 两个方向分别编码，每一位包含正常图和反相图，并通过全黑/全白参考图及黑白阈值排除阴影和低对比区域。1920×1080 若逐像素编码需要更多位；本项目按 8 像素单元编码，将图卡总数控制为 34 张，同时保留正反图差分和黑白参考图的鲁棒性设计。

### 参考结论

GitHub 参考项目证明了 Gray Code 对应关系与第二显示器投图的可行性，但它们没有直接满足本项目的特殊要求：海康 GigE C# SDK、Windows 壁纸切图、可配置自然逆映射外接尺寸、可配置点阵相机回环和文件夹批处理。因此本工程只参考公开原理和接口设计，核心代码按当前系统重新实现。

## 14. 限制与后续建议

- 标定只对当前相机、投影仪、反射面和机械位置有效；任何部件移动后应重新标定。
- 当前只校正几何畸变，不校正亮度不均、颜色、反射率或暗场噪声。
- 实投彩色壁纸时，相机锁定曝光下画面偏暗；若需要自动做彩色画质验收，应另做光度标定并保存一套“标定曝光”和一套“观察曝光”。
- 自动位置最忠实于原标定。固定位置是整体平移对照；平移较大时，非线性光路下相机观察位置也会变化，若要求固定位置仍达到亚像素误差，应在该固定位置再做一次短回环。
- 建议将每次标定的相机曝光、增益、镜头焦距、投影亮度和硬件位置写入运行记录，便于长期复现。
